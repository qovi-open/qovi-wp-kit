Plugin WordPress natif MFA par QR code zéro mot de passe Linux + Windows

🏗️ Architecture

Le kit WordPress agit comme frontend d'authentification. Le plugin qfa-login communique avec le serveur FidPub (service QfA) via WebSocket chiffré (AES/ECB/PKCS7). WordPress ne stocke aucun mot de passe — l'identité est validée par le mobile de l'utilisateur.

Flux d'authentification : 
Navigateur → WordPress (qfa-login) → FidPub (WebSocket) → Mobile (App Qovi)
                                    ←─────────────────────────────────────
                              Session WordPress créée ✅

📁 Structure du kit

qfa-wp-kit/
├── wp-admin/ 🔒 Core WordPress — ne pas modifier
├── wp-includes/ 🔒 Core WordPress — ne pas modifier
├── wp-content/
│ ├── plugins/
│ │ └── qfa-login/ ✏️ Code QfA — seul dossier à modifier
│ │     ├── qfa-login.php ✏️ Plugin principal
│ │     └── res/ 🔒 Assets JS/JSON
│ └── themes/ 🔒 Votre thème WordPress (non fourni)
└── wp-config.php ✏️ Configuration DB WordPress
💡 Principe de déploiement — le kit est un patch différentiel : copier/coller le contenu de qfa-wp-kit/ par-dessus un WordPress propre. Les dossiers wp-admin/ et wp-includes/ vides dans le kit servent de marqueurs visuels — ils rappellent que ces dossiers doivent être fournis par le WordPress cible.

⚙️ Déploiement

🐧 Linux
🪟 Windows

1. Prérequis

# Apache + PHP + module pgsql
apt update && apt install -y apache2 php php-curl php-pgsql
systemctl enable apache2 && systemctl start apache2

2. Installer WordPress

# Télécharger WordPress dans le dossier cible
cd /var/www/html
wget https://wordpress.org/latest.tar.gz
tar xzf latest.tar.gz
mv wordpress/* .
rm -rf wordpress latest.tar.gz
chown -R www-data:www-data /var/www/html/

3. Copier le kit QfA par-dessus

# CC inverse : le kit écrase uniquement ses propres fichiers
cp -r /chemin/vers/qfa-wp-kit/wp-content/plugins/qfa-login \
      /var/www/html/wp-content/plugins/
cp /chemin/vers/qfa-wp-kit/wp-config.php /var/www/html/wp-config.php
chown -R www-data:www-data /var/www/html/wp-content/plugins/qfa-login

4. Configurer Apache

# /etc/apache2/sites-available/monsite.conf
<VirtualHost *:80>
    ServerName monsite.com
    DocumentRoot /var/www/html
    <Directory /var/www/html>
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
a2ensite monsite.conf
a2enmod rewrite
systemctl reload apache2

5. HTTPS avec Let's Encrypt

apt install -y certbot python3-certbot-apache
certbot --apache -d monsite.com
✅ FidPub doit être accessible — vérifier que le service FidPub est actif sur le port configuré dans qfa-login.php et que le firewall autorise la connexion WebSocket depuis le serveur Apache.

http://localhost/wp-login.php

🔑 Configuration du plugin

Rien à modifier dans les fichiers : tout se règle dans l'administration WordPress, menu Réglages → Qovi Login.

  • Adresse du service Qovi : https://qovi.ch/RST (valeur par défaut).
  • Clé privée du site : la seule clé à copier, depuis votre espace administrateur sur qovi.ch (compte ch.qovi@votredomaine.com). Champ masqué, jamais réaffiché. Elle ne quitte jamais votre serveur : les requêtes vers Qovi sont signées.
  • Page de connexion et page après connexion.
⚠️ Prérequis serveur — l'horloge du serveur doit être à l'heure (NTP, à ±60 s près) et PHP doit pouvoir ouvrir une URL HTTPS (allow_url_fopen activé).

🔌 Activation du plugin

1
Connectez-vous à l'admin WordPress 
https://monsite.com/wp-admin/
2
Extensions → Extensions installées

Le plugin QfA Login apparaît dans la liste. Cliquer sur Activer.

3
Tester l'authentification

Ouvrir une fenêtre de navigation privée et accéder à une page protégée — le formulaire QfA doit s'afficher à la place du formulaire WordPress standard.

🛡️ Notes de sécurité

  • Le fichier wp-config.php contient les identifiants DB — ne jamais le versionner dans un dépôt public.
  • La clé privée du site (réglages du plugin, stockée dans la base WordPress) est sensible — même précaution pour les sauvegardes de la base.
  • En production, HTTPS est obligatoire — les cookies de session WordPress sont marqués Secure automatiquement.
  • L'accès à /wp-admin/ en production doit être restreint par IP ou protégé par un second facteur.

Sécurité (version d'octobre 2026)

  • La clé privée du site ne quitte jamais votre serveur. Elle n'est jamais envoyée au navigateur, ni écrite dans un journal. Elle sert seulement à signer chaque demande ; le service Qovi vérifie la signature, et votre serveur vérifie celle de la réponse.
  • La fin de connexion est vérifiée par Qovi. Votre serveur n'ouvre la session que si Qovi confirme : validation réelle sur le mobile, délai de 120 secondes, usage unique, même navigateur que celui qui a lancé la demande. L'adresse e-mail de la session est celle confirmée par Qovi, jamais celle envoyée par le navigateur.
  • Ne publiez jamais votre clé privée (dépôt git, capture d'écran, message). Si elle a pu être exposée, renouvelez-la depuis votre espace administrateur Qovi.
  • HTTPS obligatoire sur votre site.

Extension « Qovi Login » 2.3

  1. Installez un WordPress standard, puis copiez le dossier wp-content/plugins/qfa-login du kit et activez « Qovi Login ».
  2. Réglages → Qovi Login : adresse du service (par défaut https://qovi.ch/RST), clé privée (champ masqué, jamais réaffichée ; laisser vide pour ne pas la changer), page de connexion et page après connexion.
  3. Créez une page de connexion avec [qfa_login] et une autre page privée avec [qfa_private]votre contenu[/qfa_private]. Bouton de sortie : [qfa_logout]. Lien « Connexion / Déconnexion » selon l'état, à placer dans un en-tête ou un menu : [qfa_login_link].
  4. Une page devient privée par son contenu, pas par un réglage : c'est le code court [qfa_private]…[/qfa_private] qui la protège. Écrivez les codes courts avec leurs crochets, dans un paragraphe ou un bloc « Shortcode » — jamais dans un bloc « Code » (il les afficherait sans les exécuter).
  5. Testez dans une fenêtre de navigation privée : un administrateur WordPress connecté voit les pages privées sans passer par Qovi.
  6. Permaliens : choisissez « Titre de la publication » (Réglages → Permaliens). Le mode /index.php/… que WordPress choisit quand il ne peut pas écrire son .htaccess empêche l'éditeur d'enregistrer les pages.

Conseil : interdisez l'installation d'extensions en production (define('DISALLOW_FILE_MODS', true); dans wp-config.php).
